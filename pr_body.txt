💡 **What:**
Replaced O(N) array `.indexOf()` lookups with O(1) `Set.prototype.has()` checks inside `.map()` and `.filter()` iteration loops across multiple functions in `js/background.js` (such as `normalizeExtensions`, `toggle_all_disable`, and `runApplyProfile`). Also cached a redundant `recentList.indexOf(item.id)` call into a local variable.

🎯 **Why:**
Calling `indexOf` inside an iteration loop (like `.map()` or `.filter()`) turns an O(N) process into an O(N*M) process, significantly degrading performance for users with many extensions or large profiles.

📊 **Impact:**
Reduces the time complexity of building states and resolving profile changes from O(N*M) to O(N+M), providing a much faster experience as the extension list grows.

🔬 **Measurement:**
Run `pnpm test` and `pnpm run check:manifest` to verify that no regressions were introduced.
