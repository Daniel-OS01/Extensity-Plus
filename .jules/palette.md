## 2024-04-20 - Icon-Only Button Accessibility Pattern Verification
**Learning:** Adding `aria-label` to the interactive `<button>` wrappers and explicit `aria-hidden="true"` to the inner decorative FontAwesome `<i>` tags is a clean, non-disruptive accessibility enhancement for this codebase. It perfectly avoids layout shifts or CSS selector breakage (like accidentally triggering hover/active states that rely on direct parent-child relationships) that might occur if we changed the DOM structure itself.
**Action:** Always prefer this two-step attribute injection pattern for icon-only components in `index.html` to maintain CSS and logic parity while maximizing screen reader compatibility.
## 2024-05-15 - Input Accessibility Pattern Verification
**Learning:** Adding a `placeholder` and `aria-label` to standalone search input fields without an explicit `<label>` tag drastically improves screen reader usability while providing visual context. Simultaneously hiding the adjacent decorative FontAwesome search icon (`<i class="fa fa-search" aria-hidden="true"></i>`) reduces cognitive load and repetitive announcements for screen reader users. The same `aria-hidden="true"` principle applies well to empty state icons (`fa-exclamation-triangle`) to avoid noise.
**Action:** Consistently apply this pattern for inputs and adjacent descriptive icons across the codebase to ensure functional clarity and reduce screen reader noise.
