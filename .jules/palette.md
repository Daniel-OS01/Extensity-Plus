## 2024-04-20 - Icon-Only Button Accessibility Pattern Verification
**Learning:** Adding `aria-label` to the interactive `<button>` wrappers and explicit `aria-hidden="true"` to the inner decorative FontAwesome `<i>` tags is a clean, non-disruptive accessibility enhancement for this codebase. It perfectly avoids layout shifts or CSS selector breakage (like accidentally triggering hover/active states that rely on direct parent-child relationships) that might occur if we changed the DOM structure itself.
**Action:** Always prefer this two-step attribute injection pattern for icon-only components in `index.html` to maintain CSS and logic parity while maximizing screen reader compatibility.
## 2024-05-18 - Accessibility: Icon-Only Buttons
**Learning:** Wrapping decorative icons (`<i>` tags) with semantic `<button type="button">` wrappers and transferring data bindings is a highly effective, low-risk way to dramatically improve screen reader and keyboard accessibility in Knockout.js applications without breaking visual layouts. Using an inline style reset coupled with a `!important` modifier on CSS pseudo-classes ensures hover states are maintained across legacy stylesheets.
**Action:** Always prefer this two-step structural injection pattern (semantic button wrapper + hidden inner icon) over attempting to make non-interactive elements accessible via ARIA roles and tabindex tricks.
