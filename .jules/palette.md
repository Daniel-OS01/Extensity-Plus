## 2024-04-20 - Icon-Only Button Accessibility Pattern Verification
**Learning:** Adding `aria-label` to the interactive `<button>` wrappers and explicit `aria-hidden="true"` to the inner decorative FontAwesome `<i>` tags is a clean, non-disruptive accessibility enhancement for this codebase. It perfectly avoids layout shifts or CSS selector breakage (like accidentally triggering hover/active states that rely on direct parent-child relationships) that might occur if we changed the DOM structure itself.
**Action:** Always prefer this two-step attribute injection pattern for icon-only components in `index.html` to maintain CSS and logic parity while maximizing screen reader compatibility.
## 2024-05-18 - Convert Interactive Icon-Only Elements to Buttons
**Learning:** Found multiple instances where interactive icon-only elements (like the gear icon for Options and the trash icon for removing profiles) were implemented using just `<i>` tags with `click` bindings. These elements lacked proper accessibility since they weren't focusable and couldn't be easily identified by screen readers. Wrapping or replacing them with a `<button type="button">` structure (and resetting default button styles with `style="background:none; border:none; padding:0; cursor:pointer;"`) fixes the a11y problem while preserving existing UI appearance.
**Action:** Always scan for interactive `<i>` or `<span>` tags using Knockout `click` bindings. Convert them into standard `<button>` tags with `aria-label`s, moving the `data-sbind` bindings to the `<button>`, and adding `aria-hidden="true"` to the inner `<i>` tag.
