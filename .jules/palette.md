## 2024-04-20 - Icon-Only Button Accessibility Pattern Verification
**Learning:** Adding `aria-label` to the interactive `<button>` wrappers and explicit `aria-hidden="true"` to the inner decorative FontAwesome `<i>` tags is a clean, non-disruptive accessibility enhancement for this codebase. It perfectly avoids layout shifts or CSS selector breakage (like accidentally triggering hover/active states that rely on direct parent-child relationships) that might occur if we changed the DOM structure itself.
**Action:** Always prefer this two-step attribute injection pattern for icon-only components in `index.html` to maintain CSS and logic parity while maximizing screen reader compatibility.

## 2024-05-18 - Replacing interactive icons with inline buttons for a11y
**Learning:** Found interactive `<i>` tags serving as icon-only actions (like the `remove-profile` delete button in `profiles.html`). While they look like standard icons, relying on inline click handlers directly on non-semantic tags like `<i>` creates poor keyboard accessibility because they don't natively receive focus or `Enter`/`Space` interactions.
**Action:** Replace interactive icon tags with a clean `<button type="button">` wrapper around the `<i>` tag, explicitly resetting its style using `style="background:none; border:none; padding:0; cursor:pointer;"` to preserve its inline appearance. Always move CSS class hooks, JavaScript click bindings (`data-sbind`), and `title` attributes from the `<i>` up to the new `<button>` wrapper. Finally, add an appropriate `aria-label` to the button and set `aria-hidden="true"` on the child `<i>` icon to ensure perfect screen reader integration without altering visual flow.
