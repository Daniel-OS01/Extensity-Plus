## 2024-04-20 - Icon-Only Button Accessibility Pattern Verification
**Learning:** Adding `aria-label` to the interactive `<button>` wrappers and explicit `aria-hidden="true"` to the inner decorative FontAwesome `<i>` tags is a clean, non-disruptive accessibility enhancement for this codebase. It perfectly avoids layout shifts or CSS selector breakage (like accidentally triggering hover/active states that rely on direct parent-child relationships) that might occur if we changed the DOM structure itself.
**Action:** Always prefer this two-step attribute injection pattern for icon-only components in `index.html` to maintain CSS and logic parity while maximizing screen reader compatibility.
## 2024-07-22 - Accessible Semantic Buttons for Icon-Only Actions
**Learning:** Adding `aria-label` to interactive elements and wrapping decorative FontAwesome `<i>` tags in semantic `<button type="button">` wrappers is an essential accessibility enhancement. Using inline styles for a basic reset (`background:none; border:none; padding:0; cursor:pointer; color:inherit;`) preserves the existing visual layout, avoiding disruptive visual regressions while making the components fully screen reader and keyboard navigable. When doing this, hover styles that modify color must append `!important` to override the inline `color: inherit;`.
**Action:** Prefer wrapping interactive icons in semantic `<button>` elements with inline resets and `aria-label`s across all templates to maintain CSS parity while maximizing a11y compatibility. Ensure related `:hover` CSS classes use `!important` for inherited properties.
